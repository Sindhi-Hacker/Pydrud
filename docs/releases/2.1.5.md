**Material 3 Complete — the largest design-system upgrade in Pydrud history.**

This release takes the framework from roughly half of Material 3 to what the
spec actually describes: the HCT colour system with all 49 roles, a dozen new
components, the type/shape/motion scales as published tokens, a stylesheet
language that reaches every widget, and the icon and shape systems Material
is built on. Android remains the only renderer Pydrud ships; the widget,
theme and styling layers stay platform-neutral.

## Colour

* **A real HCT/CAM16 implementation** (`pydrud/widgets/theme/hct.py`) with the
  spec's tone and chroma handling. The previous scheme picked pleasant
  colours; this one solves for them.
* **All 49 Material 3 roles** — the standard 26 plus the fixed accents, the
  surface container ladder and the inverse roles. `$primary`, `$surface_container_high`
  and `$md_sys_color_on_surface` all resolve to the same palette.
* **Shadow and scrim are the spec's black.** Both roles had drifted to a
  tinted grey; the opacity belongs to the component that composites it, so a
  modal drawer now dims the page at the spec's 32 %.

## Components

* **Twelve new Material 3 components**: snackbar, the date/time/date-range
  pickers, standard and side sheets, full-screen dialog, bottom app bar, FAB
  menu, search view, button group, split button, loading indicator and
  toolbar.
* Every one is a native Android view; none is a web view or a canvas
  look-alike.

## Tokens

* **Typography, shape and elevation match the published tables** — the type
  scale with its line heights and tracking, the corner-radius scale, and the
  L0–L5 tonal elevation ladder.
* **Motion is the spec's curves**, not approximations: the seven easing
  tokens hold the real cubic-béziers, and durations can be named as the spec
  names them (`$duration_medium_2`, `medium-2`, `300ms`).
* **Every published token now changes the screen.** The token table used to
  contain values nothing read; each one is now rendered, part of a
  pick-from scale, or documented chrome — and a test enforces it.

## Icons

* **The Material Symbols variable axes reach the glyph.** `weight`, `fill`,
  `grade` and `optical` are settable on `Icon(...)` and `Icon.svg(...)`,
  clamped to the ranges the font declares, modelled on the shipped paths by
  the renderer, and settable from a stylesheet (`icon-weight`, `icon-fill`,
  …).

## Shapes and motion

* **Material 3 springs.** The six springs the spec publishes are tokens with
  an analytic evaluator on both sides of the bridge, so a spring means the
  same thing in Python and on the device. Spatial springs may overshoot;
  effects springs are critically damped.
* **Shape morphing.** The Material shape family — circles, rounded polygons,
  puffy squircles and the cookie/clover/burst/flower waves — drawn from
  radius functions sampled at matching angles, with `ShapeMorph` interpolating
  between any two members on a spring.

## Stylesheets (PSS)

* **Every declaration reaches the screen.** The cascade is widget default <
  stylesheet < caller, and a declaration that cannot be honoured is reported
  instead of dropped silently.
* Pseudo-classes become renderer state specs, `@media`, `@keyframes`,
  `transition` and the CSS long-hands all fold into the canonical form the
  renderer consumes.

## Platform

* **RTL is real**: logical insets and margins survive the round trip, and a
  right-to-left layout mirrors without the app doing anything.
* Android-only renderers, with the UI layer kept portable — adding a platform
  means adding one adapter, not forking the design system.

## Verification

* 1672 tests, 3241 subtests, green.
* 35/35 generated Java templates parse; 0 unresolved cross-class symbols.
* The wheel ships every template and the CLI runs from a clean install.
